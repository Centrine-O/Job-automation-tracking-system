04 — Scoring Engine

Two scores, both must pass

Every job receives two independent AI scores before the system spends any effort on it. Both must hit 65+ or the job is discarded.

Score A — Skill Match
Does this job match your profile?

AI reads the full JD and scores 0–100 against your target roles: data analysis, software engineering, AI, automation.

SignalPoints
Core role match (data / software / AI)+40
Automation / Python / SQL keywords+20
Seniority appropriate (junior–mid)+20
Technologies in your stack+20
Hard degree requirement not met-20

Threshold: ≥ 65 to proceed

Score B — Hire Probability
Will they hire a Kenyan?

AI scans for signals that indicate openness to African/Kenyan candidates, or hard blockers that would guarantee rejection.

SignalPoints
Mentions Kenya / Africa / Nairobi+30
Remote-first / distributed team+25
No visa/work-auth requirement+25
Salary listed (transparency signal)+10
“Must be authorized to work in US/UK/EU”-60
“Local candidates only”-50
On-site in non-African city, no remote option-40

Threshold: ≥ 65 to proceed

05 — CV Engine

ATS-first. Role-specific. Self-verifying.

Every CV generated must pass an ATS simulation before it is ever submitted. Keyword engineering is treated as a hard requirement, not a nice-to-have. The system regenerates until it passes.

ATS Compliance Rules — Non-Negotiable
Every generated CV must satisfy all of these before submission
Format Rules (Parser Safety)
  • Single column layout only — no tables used for structure
  • No text boxes, headers/footers, images, graphics, or skill bars
  • Standard section names: EXPERIENCE, SKILLS, EDUCATION, PROJECTS
  • Fonts: Arial or Calibri only — fully embedded, selectable text
  • Output in both PDF and .docx — system picks format per ATS type
  • No special characters that break ATS parsers (&, ★, ●, etc.)
  • Contact info in plain text at the very top — not in a header element
  • Consistent date format throughout: Jan 2024 – Mar 2025
Keyword Rules (Score Maximisation)
  • Every required skill from the JD must appear verbatim at least once
  • Use exact JD phrasing — if JD says “ML” the CV says “ML”, not “machine learning”
  • Include both acronym AND full form where JD uses both
  • Job title in CV summary must mirror or closely echo the target role title
  • Skills section lists JD-matching skills first, ranked by JD prominence
  • Preferred/nice-to-have skills included if present in master CV
  • Soft skills mentioned in JD woven into experience bullets naturally
  • Every experience bullet quantified: numbers, percentages, or outcomes
ATS Generation Pipeline
What happens for every qualifying job
1

AI extracts keyword map from JD

Required skills, preferred skills, technologies, methodologies, soft skills, role title keywords — all extracted as a structured list

2

Keyword gap analysis against master CV

Each required keyword checked: present in master CV? Can it be truthfully added from experience? Gap keywords flagged.

3

AI writes role-specific CV draft

Summary rewritten for this exact role. Skills reordered. Relevant projects promoted. JD keywords woven into every bullet.

4

ATS self-score simulation

Python counts exact keyword matches between the generated CV text and the JD keyword map. Calculates coverage score (0–100).

5

Score ≥ 85%? Pass → generate files

Outputs ATS-safe PDF (ReportLab) + .docx (python-docx). Both filed to /storage/applications/{job_id}/

6

Score < 85%? Regenerate with feedback

Missing keywords fed back into the prompt. AI rewrites with explicit instruction to include each missing term. Max 3 attempts — if still failing, flagged in dashboard for manual review.

09 — Security Architecture

Every layer has explicit mitigations

You're storing personal data, CV content, and credentials. Nothing is assumed safe by default.

VPS Hardening
Oracle Cloud VPS
  • SSH key-only auth — password disabled on day 1
  • UFW firewall: only ports 22, 80, 443, 5678 (n8n)
  • Fail2ban: auto-ban repeated SSH failures
  • Non-root user for all application processes
  • Unattended security upgrades enabled
  • n8n behind Nginx with Let’s Encrypt HTTPS
Credential Management
Secrets & API Keys
  • .env file — never committed to git
  • .gitignore blocks .env, tokens/, storage/, data/
  • Gmail: OAuth2 refresh token only (no password stored)
  • AI API keys: read from env at runtime
  • Dashboard: DASHBOARD_USER + DASHBOARD_PASS + SECRET_KEY in .env
  • n8n credentials: encrypted in its own SQLite DB
Scraping Ethics
Staying under the radar
  • Randomised delays: 3–9 seconds between requests
  • Rotating User-Agent strings per session
  • Realistic viewport: 1920×1080
  • LinkedIn: session cookies, max 50 req/day
  • robots.txt respected — disallowed paths skipped
  • Exponential backoff on 429 responses
Data Privacy
Your personal data
  • CV data stays on your VPS — not sent to any SaaS
  • AI calls send only JD excerpts (not full CV) for scoring
  • Logs redact email addresses and phone numbers
  • Playwright screenshots stored locally only
  • SQLite on encrypted Oracle block volume
Threat Model
Known risks & mitigations
LinkedIn account ban
High risk if scraping aggressively
Max 50 req/day, human delays, session cookies. Scrape search results only — not profiles.
Gemini/Groq rate limit
Blocks applications mid-pipeline
Fallback chain (Gemini → Groq → Ollama). Token usage tracked — pauses if limit near.
Playwright form errors
Silent failed submission
Screenshot every step. Exceptions caught, flagged in Sheets as “Needs Manual”, Telegram alert sent.
Gmail spam reputation
Application emails land in spam
Max 15/day, proper MIME formatting, professional templates, no bulk send headers.
VPS compromise
API keys and CV exposed
UFW firewall, SSH key only, Fail2ban, non-root user, automatic security patches.
