CV Generation Engine
Keyword extraction · ATS self-scoring loop · PDF + DOCX output
Complete 8 tasks ►

Goal: Given a job description, generate a tailored CV that passes any ATS system. The engine extracts keywords from the JD, scores the current draft, and regenerates until keyword coverage is ≥85%. Outputs both a PDF (ATS-safe single-column ReportLab) and a .docx (python-docx). Every keyword must appear verbatim in the CV — no paraphrasing.

Tasks
Write keyword_extractor.py — extract and rank ATS keywords from job description
Use AI to identify: required technical skills (Python, SQL, etc.), tool names (dbt, Airflow, etc.), soft skills used in ATS (cross-functional, stakeholder), job title variants, certifications mentioned. Return as ranked list with frequency weight.
Pending
Write ats_scorer.py — simulate ATS keyword scan, return coverage %
Input: cv_text (plain string), keyword_list (from extractor) · For each keyword: check verbatim match (case-insensitive) in cv_text · coverage = matched / total × 100 · Return: score, matched list, missing list
Pending
Write Jinja2 prompt template cv_tailor.j2
Inputs: master_cv_json, job_description, missing_keywords, iteration (1-5) · Instruction: rewrite experience bullet points to naturally incorporate all missing_keywords verbatim · Preserve all factual information — do NOT invent experience · Output: structured JSON matching master_cv.json schema
Pending
Write tailor.py — self-scoring generation loop until ATS score ≥85%
Loop max 5 iterations: 1) Extract keywords from JD → 2) Render cv_tailor.j2 with missing keywords → 3) Call AI → 4) Score result → 5) If <85%, identify still-missing keywords, regenerate → After 5 tries, use best result. Store final ats_score in applications table.
Pending
Write cover_letter.py and Jinja2 template cover_letter.j2
Template inputs: master_cv_json, job_description, company_name, role_title, matched_skills · Output: 3-paragraph professional cover letter. Para 1: why this specific company + role. Para 2: relevant experience matching JD. Para 3: call to action. No generic templates.
Pending
Write pdf_generator.py — ATS-safe PDF using ReportLab
Rules: single-column layout (no tables for layout), Helvetica or Arial font only (ATS-safe), no images or logos, no text boxes, bullet points as plain hyphens or en-dashes, standard section headers (Experience, Skills, Education), all text selectable. Output to storage/applications/{job_id}/cv.pdf
Pending
Write docx_generator.py — Word format using python-docx
Use built-in Word styles (Heading 1, Heading 2, List Bullet) · No custom fonts (use Calibri which is ATS-safe) · Set document metadata: author, title · Output to storage/applications/{job_id}/cv.docx
Pending
Integration test: generate CV for 3 real jobs, manually verify ATS score ≥85%, open PDF + DOCX and visually inspect
Use a free ATS checker (Jobscan, Resume Worded free tier) to validate the PDF is actually ATS-readable. Adjust pdf_generator if any formatting causes parse failures.

Application Submission
Gmail API · Playwright + AI form filler · Cover letter PDF · Rate limiting
Complete 6 tasks ►

Goal: The system can deliver a job application two ways — email (CV attached, short AI-generated cover letter) and web form (Playwright opens the browser, user reviews and submits). Applications are spread across an 8am–5pm window, max 15/day. A minimal FastAPI dashboard shows the review queue and full application history.

APScheduler (inside FastAPI process)
    │
    ├── Every 2 hours (8am–5pm): Scraper → Scorer → CV + Cover Letter Generator
    │       Picks top qualified jobs by score, marks as "ready"
    │
    ├── Email jobs → Gmail API → sent automatically → marked "applied"
    │
    └── Form jobs → Playwright + AI Form Filler (fully automated)
                         │
                         ├── Navigate to apply_url
                         ├── Read all form fields + question labels
                         ├── AI generates answers for every field:
                         │       • Standard fields  → name, email, phone, location from profile
                         │       • File uploads     → attach tailored CV + cover letter PDF
                         │       • Open-ended Qs   → AI writes answer using JD + candidate profile
                         │       • Salary fields    → AI researches role/location market rate
                         │       • Dropdowns/radio  → AI selects best matching option
                         ├── Fill all fields → submit form → screenshot confirmation
                         └── Mark "applied" in DB
                                  │
                                  └── EXCEPTION only (captcha / login wall / unrecognised structure)
                                            ↓
                                  Flagged as "needs_review" in Dashboard queue
                                  User completes remaining fields, submits, marks done

FastAPI app on localhost:8000
    ├── /            → Dashboard: stats, today's activity, pipeline health
    ├── /queue       → Exception queue (only stuck/failed form jobs)
    ├── /history     → All applications with status and screenshots
    └── /apply/{id}  → Re-triggers Playwright for a flagged job
